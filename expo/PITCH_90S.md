# 90-Second Live Demo Pitch

## 0–15 seconds — Problem

> Security AI is increasingly able to detect attacks and recommend or execute responses. But there is a fundamental problem: an AI action can stop an attack and still break the infrastructure.

Point to the normal system state.

## 15–30 seconds — Attack

Start the brute-force scenario.

> Here we have a credential brute-force attack against an IoT service. INVERIQ detects the threat and maps it to MITRE ATT&CK T1110.

Show the threat card and confidence score.

## 30–50 seconds — Candidate actions

> The response engine generates multiple mitigation candidates. Several of them can stop the attacker, but that does not mean they are safe.

Show the candidate comparison.

## 50–70 seconds — Verification

Highlight the unsafe candidate.

> This action would stop the attack, but it also violates reachability, availability, and blast-radius requirements. INVERIQ rejects it before it can reach the infrastructure.

Then highlight the verified candidate.

> This alternative passes all six verification gates: authorization, target, reachability, availability, blast radius, and security effectiveness.

## 70–85 seconds — Enforcement

Execute the verified action.

> Only after verification does INVERIQ allow the mitigation to be enforced. The attack is reduced while legitimate connectivity remains available.

Show post-verification metrics.

## 85–90 seconds — Close

> **AI decides. INVERIQ verifies.**

Optional follow-up:

> We are building INVERIQ as a verification layer for autonomous cyber defense across IoT, Edge, Cloud, and operational infrastructure.
