# INVERIQ v0.7.0 — Real Testbed Instrumentation

v0.7.0 replaces the most important synthetic demo KPIs with measurements collected directly from the isolated Docker lab.

## Real measurements

The release records:

- actual wall-clock detection command latency;
- actual verification execution latency;
- actual nftables enforcement command latency;
- total measured closed-loop latency;
- trusted-client HTTP health before and after mitigation;
- trusted-client HTTP latency before and after mitigation;
- nftables packet counters before and after mitigation;
- gateway container CPU/memory/network statistics;
- whether all verification gates passed.

## Safety boundary

All enforcement remains limited to the `inveriq-gateway` container. No host firewall rule is installed.

## Collect a telemetry snapshot

```bash
python scripts/collect_instrumentation.py --label pre
```

## Run a real benchmark cycle

```bash
python scripts/benchmark_real.py --scenario brute-force
```

Alternative scenarios:

```bash
python scripts/benchmark_real.py --scenario ddos
python scripts/benchmark_real.py --scenario exfiltration
```

Reports are written to:

```text
.demo-state/reports/<run-id>-real.json
.demo-state/reports/runs-real.csv
```

## Dashboard

Run:

```bash
streamlit run dashboard/app.py
```

The `Real Testbed Instrumentation` panel reads `runs-real.csv` and shows the latest measured values.

## Important limitation

v0.7.0 measures the real execution path and live service health, but attack-rate reduction is not yet calculated from packet-level attack generators. The next release should add explicit per-scenario traffic generators and counters so effectiveness can be measured from actual attack traffic rather than inferred from service state.
