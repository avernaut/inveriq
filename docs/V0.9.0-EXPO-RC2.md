# INVERIQ v0.9.0-expo-rc2 — Expo RC Hardening

This release is the second feature-frozen release candidate for the IoT Tech Expo Europe 2026 demonstration. It intentionally adds no demo features; it focuses on release correctness, reproducibility, and enforcement-input safety.

## Fixed

- Restored executable permissions for the demo and lab shell launchers.
- Removed stale API version reporting (`0.4.0`) and centralized runtime release metadata.
- Updated package metadata to the PEP 440 prerelease version `0.9.0rc2` while retaining the GitHub tag `v0.9.0-expo-rc2`.
- Corrected the README development status to point to the current Expo RC line.

## Security hardening

- `MitigationCandidate.source` now accepts only valid IP addresses or CIDR networks.
- Candidate identifiers are constrained to a safe identifier syntax.
- Blast-radius and duration values now have explicit model bounds.
- Mitigation actions use a closed typed vocabulary.

These checks strengthen the boundary before nftables rendering and reduce the risk that future untrusted candidate-generation paths could pass command-language fragments to enforcement code.

## Reliability / CI

- Added GitHub Actions CI for Python 3.12.
- CI compiles Python sources, runs the complete pytest suite, and verifies executable demo launchers.
- Added regression tests for release metadata consistency, executable-bit preservation, and rejection of non-IP enforcement sources.

## Release identifiers

- GitHub release/tag: `v0.9.0-expo-rc2`
- Python package version: `0.9.0rc2`

## Validation

Run locally:

```bash
python -m compileall -q inveriq dashboard scripts demo tests
python -m pytest -q
```

For the isolated Expo validation path:

```bash
demo/run_expo_rc.sh brute-force
```

The Expo freeze remains in force: only defect, reliability, documentation, and security fixes should be merged before the event.
